# 로컬 배포와 실행 안내

이 과제는 본인 PC에서 프론트 빌드 결과, 백엔드와 SQLite 파일 DB가 함께 동작하도록 완성합니다. 교수자는 GitHub 저장소를 clone한 뒤 README의 명령으로 실행합니다. GitHub에 코드를 올리는 것만으로 서비스가 실행되지는 않습니다. 공개 웹사이트 주소나 유료 서버는 필요하지 않습니다.

## 1 준비

- ZIP을 풀고 `JWT-Assignment` 폴더를 엽니다. 아래 명령은 이 폴더에서 시작합니다.
- 프론트 React/Vue 중 하나, 백엔드 Express/FastAPI/Spring 중 하나를 선택합니다.
- Node.js 20.19 이상을 설치합니다. FastAPI 선택 시 Python 3.10 이상, Spring 선택 시 JDK 17 이상도 설치합니다.
- 최초 의존성 설치와 Maven 다운로드에는 인터넷이 필요합니다. 제공 코드는 별도 DB 서버 없이 로컬 SQLite 파일을 자동 생성합니다.
- 두 터미널을 사용합니다. 터미널 A는 백엔드, 터미널 B는 프론트입니다. 각 포트에는 한 서버만 실행하세요.

## 2 터미널 A에서 선택한 백엔드 실행

아래 세 가지 중 하나만 실행합니다. 시작 코드의 인증은 미완성이므로 첫 실행에는 JWT 없이 CRUD를 확인할 수 있습니다. JWT 구현 후에는 각 백엔드 README에 따라 직접 생성한 JWT_SECRET과 TOKEN_TTL을 설정합니다. 예시 키나 실제 키를 제출 저장소에 올리지 마세요.

### Express

Windows PowerShell과 macOS/Linux에서 동일합니다.

```sh
cd backend-express
npm ci
npm start
```

JWT 구현 시 `.env.example`을 `.env`로 복사하고 새 키를 설정합니다. macOS/Linux는 `cp .env.example .env`, PowerShell은 `Copy-Item .env.example .env`를 사용합니다. 실행 명령은 그대로 `npm start`입니다.

### FastAPI

macOS/Linux:

```sh
cd backend-fastapi
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Windows PowerShell:

```powershell
cd backend-fastapi
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

JWT 구현 시 `.env.example`을 `.env`로 복사해 새 키를 설정합니다. 실행 시 가상환경의 Python을 사용하고, 최종 확인에는 자동 재시작 옵션 없이 위 명령을 사용합니다.

### Spring Boot

macOS/Linux:

```sh
cd backend-spring
chmod +x mvnw
./mvnw package
java -jar target/jwt-board-1.0.0.jar
```

Windows PowerShell:

```powershell
cd backend-spring
.\mvnw.cmd package
java -jar target/jwt-board-1.0.0.jar
```

JWT 구현 후에는 java 명령을 실행할 터미널에서 환경변수를 설정합니다. Spring은 `.env`를 자동으로 읽지 않으므로 `env.example.txt`와 백엔드 README를 따르세요. 개발 중에는 `./mvnw spring-boot:run` 또는 `.\mvnw.cmd spring-boot:run`을 사용할 수 있습니다.

### 백엔드 확인

브라우저에서 http://127.0.0.1:8000/api/health 를 열어 `status`가 `ok`인지 확인합니다. 백엔드 터미널은 실행 상태로 유지합니다.

## 3 터미널 B에서 프론트 빌드와 실행

새 터미널을 과제 루트에서 열고 실행합니다. Vue 선택 시 첫 줄을 `cd frontend-vue`로 바꾸세요. Windows PowerShell과 macOS/Linux에서 명령은 동일합니다.

```sh
cd frontend-react
npm ci
npm run build
npm run preview
```

브라우저에서 http://127.0.0.1:4173 을 엽니다. 프론트가 `/api`로 보내는 요청은 로컬 백엔드의 8000번 포트로 전달됩니다. 빌드된 `dist/index.html` 파일을 직접 더블클릭하지 마세요. 프론트와 백엔드 프로세스가 모두 켜져 있어야 합니다.

개발할 때는 `npm run dev`를 실행하고 http://127.0.0.1:5173 에 접속합니다. 최종 확인은 `npm run build` 후 4173번에서 수행합니다. Vite preview는 로컬 빌드 확인용 서버입니다.

## 4 확인과 종료

1. 시작 코드: 글 등록·목록·상세·수정·삭제와 새로고침을 확인합니다. 로그인 TODO 안내와 로그인 API의 501 응답은 미완성 상태에서 정상입니다.
2. 완성 코드: Alice/Bob으로 로그인, JWT 전송, 본인 글 권한과 토큰 오류를 `05_테스트시나리오.md`의 T01~T17에 따라 확인합니다.
3. 백엔드를 Ctrl+C로 종료하고 같은 백엔드 폴더에서 다시 실행해 기존 게시글이 남는지 확인합니다. 로그인 상태는 새로고침 시 해제되는 것이 정상입니다.
4. 작업을 끝내면 프론트와 백엔드 터미널에서 각각 Ctrl+C를 누릅니다. 브라우저를 닫는 것만으로 서버가 종료되지는 않습니다.

세 백엔드 모두 SQLite를 사용하며 기본 DB는 `data/board.sqlite`입니다. 해당 백엔드 폴더를 기준으로 생성합니다. 각 백엔드는 자신의 DB 파일을 사용합니다. 같은 파일을 여러 백엔드 프로세스에서 동시에 열지 마세요. 일반 재실행 때 지우지 마세요. 초기화하려면 먼저 서버를 종료하고 해당 실습 DB만 삭제합니다.

## 5 제출 전 새 폴더에서 재현

완성본을 GitHub에 push한 뒤 새 폴더로 clone하고, 선택한 백엔드의 환경설정과 의존성 설치부터 다시 진행합니다. 프론트도 `npm ci`, `npm run build`, `npm run preview`를 다시 실행합니다. DB와 테스트 계정이 자동 준비되어야 합니다.

README에는 실제 폴더명, OS와 버전, 설치·빌드·실행·종료 명령, 4173번 접속 주소, 8000번 API 주소, 키 설정 방법, 테스트 계정과 DB 경로를 작성하세요. 보고서에는 빌드 성공 로그, 로컬 접속 및 API 연결 화면, 재시작 후 데이터 유지 결과와 JWT 테스트 증거를 포함합니다.

설치 의존성, `dist/`, `target/`, `.venv/`, 실제 `.env`, DB와 비밀 키는 커밋하지 않습니다. 소스와 의존성·설정 예시만으로 새 빌드가 가능해야 합니다. 보고서 PDF와 테스트 증거는 GitHub에 포함하고 저장소 URL과 제출 기준 커밋 SHA를 LMS에 제출합니다.

## 실행 문제 해결

- 포트 사용 중: 먼저 본인이 실행한 이전 서버를 Ctrl+C로 종료합니다. 프론트는 다른 포트로 자동 이동하지 않도록 설정되어 있습니다.
- API 연결 실패: 8000번 health부터 확인합니다. 백엔드 포트를 바꾸었다면 `vite.config.js`의 `server.proxy`와 `preview.proxy`를 모두 바꾸고 프론트 서버를 다시 시작하세요.
- 프론트 변경이 안 보임: preview를 종료하고 `npm run build` 후 다시 실행합니다.
- 서버 재시작 후 글이 사라짐: 같은 백엔드 폴더에서 실행했는지와 DB 파일 위치를 확인합니다.
- JWT 구현 후 서버 시작 실패: 예시 키를 교체했는지, 해당 서버 프로세스에 환경설정이 전달되었는지 확인합니다. 실제 키는 로그나 보고서에 남기지 않습니다.
